# 为什么: 收藏（方案 C）与筛选保持

## 背景

面板已经能把"值不值得"算给用户看（Q 分/置信度/惩罚项），但用户**人工逐条确认**的判断没有任何容器：看完就消失在滚动里。用户要的是三件事：把候选收进收藏并在独立 tab 查看、常规页能看出哪些被收藏过、刷新后筛选不丢。

更重要的是用户给出的定位：**收藏是标注数据**——"这些都是我逐条确认过的"。因此收藏记录不能只是布尔星标，必须带**收藏时的信号快照**（Q 分/置信度/等级/阶段/价格/剩余/速度/聪明铸造者/惩罚项/日历收录），将来才能与实际结果（是否售罄、我们是否铸到、回填净值）按 `chain|contract` 关联，回答"我认为好的项目后来真的好吗、我的判断在哪些信号上最准"。

## 目标

- **收藏**：星标按钮（名称列）、独立 tab（含"已不在板面"分区）、常规页可见
- **持久化（方案 C）**：服务端 `.favorites.json`（原子写）+ `GET/POST /api/favorites`；`--report` 静态打开回退 localStorage，并在页面上明示
- **增强**：备注 + 标签（观察/准备/放弃）、收藏时间、一键导出 shortlist 与 `targets.json`（接 B 阶段执行）
- **分析导出**：`GET /api/favorites?format=jsonl` 与 CLI `--export-favorites <file>`
- **筛选保持**：筛选/排序/当前 tab 写进 URL hash（可分享），localStorage 仅作无 URL 时的默认值

## 不在本包

- 收藏与执行结果的自动关联（等 B 阶段的回执/账本落地后做分析视图）
- 多用户/账号（服务端就是单用户，Caddy basic_auth 已保护）

## 风险

| 风险 | 应对 |
|---|---|
| 静态页面无服务端 | 自动回退 localStorage，页面明确提示"仅本浏览器" |
| 收藏的目标已从板面消失 | 收藏记录保留身份字段，tab 里单列"已不在板面" |
| 页面与文件并发写 | 服务端每次请求读写整个小 JSON + 临时文件 rename；面板乐观更新、失败回滚并提示 |
| 快照字段以后会变 | 快照是"当时看到什么"的记录，加字段只追加不删除，分析端容忍缺字段 |
