# 为什么: B5 执行队列 + 面板按钮 + 独立执行器

## 背景

B1/B2/B3 把"发出去的那一下"做对了（回执核数量、三道门、burst），但触发方式仍是终端里的 `npm start -- --batch --retry-pending`。用户的实际工作流是：在面板上逐条确认、收藏（方案 C 还记了信号快照），然后**希望点一下就开始等**，而不是复制合约地址、手改 JSON、SSH 执行。

同时有一条不能破的既有防线：`--serve` 是 **fail-closed 无密钥**的（启动断言环境无私钥）。因此"面板按钮 → 花钱"绝不能把私钥塞进 serve。

## 目标

- 面板：行/收藏批量 **「加入执行队列」**；队列区块显示 `排队中/执行中/已完成/失败/已跳过`、tx 链接、`mintedCount`；**启用执行**开关（武装）；可选 dry-run 预览
- 队列是磁盘状态（`queue/*.json`），重启不丢；只有**未认领**可取消
- 执行器是**独立进程/独立 systemd 单元**（`nft-executor`），持私钥、消费队列、复用现有 `batch` 管线（含 B1/B2/B3 与账本去重）
- serve 进程永远拿不到私钥（继续断言）

## 不在本包

- 自动策略（例如"收藏标记为准备 → 自动入队"）：先把手动一键做扎实，策略另议
- 多执行器水平扩展 / 远程执行机（us-east-2 搬迁属于运维，不属代码）
- 通知渠道（Telegram/ntfy）：先日志 + 面板，若你要再加 webhook

## 风险与对策

| 风险 | 对策 |
|---|---|
| 误触花钱 | 默认**未武装**；武装状态落盘但每次重启回到未武装（可配置）；入队时展示预估成本（value+gas） |
| 私钥进入 serve | 队列文件只含目标与参数；serve 只写文件、不读密钥；执行器单独 `.env.executor`，并由 systemd 单元做文件权限与沙箱 |
| 执行器崩溃留下"执行中"僵尸任务 | 认领写 `leaseExpiresAt`；超过 5 分钟未完成可被重新认领（最多 2 次），之后标 `failed` 需人工 |
| 与 CLI 手动执行冲突 | 执行器启动时对 `.batch-state.json` 与队列目录加互斥（沿用 run-lock 思路），手动跑 batch 会被提示 |
| 队列被塞垃圾 | API 校验（链白名单/地址正则/数量上限/预算上限），并限制队列长度与每小时入队数 |
